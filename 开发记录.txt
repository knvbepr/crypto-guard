==============================================
        加密卫士 开发记录（对话总结）
==============================================

项目从一句需求开始——“做一个加解密网页，上传文件加密为
专有格式，支持图片/视频/文本，可保存”——最终发展为三端
（网页 / Windows / 安卓）完全互通的成品，并发布到 GitHub。

----------------------------------------------
一、开发时间线（按顺序）
----------------------------------------------

1. 网页版初版
   单文件加解密，AES-256-GCM + PBKDF2（60 万次迭代），
   图片 / 视频 / 文本解密后预览与保存。

2. 网页版重做（Material Design 1 风格）
   密码直接写入加密文件名（文件名__pwd_密码.enc）；
   多文件自动打包为一个密文，解密自动拆包、可导出 ZIP；
   全部图标改为矢量图标（无 emoji）。

3. Windows 版
   纯 Win32 API + 系统自带 bcrypt.dll 加密；
   TinyCC 编译，单文件 exe（约 58 KB），免安装；
   支持拖拽、多选、打包、ZIP 导出。

4. 安卓版
   无主题经典界面（安卓 2 时代风格）；
   纯 Java 无第三方依赖，手工流水线构建 APK
   （javac + d8 + aapt2 + apksigner）；
   约 33 KB，无需任何权限。

5. 三端图标（靛蓝底 + 白色挂锁）
   Node 脚本生成 .ico 与多密度 PNG；
   exe 用 UpdateResource 注入，APK 打进资源。

6. Safari 兼容
   浏览器没有 WebCrypto 时自动切换内置纯 JS 加密
   （SHA-256 / HMAC / PBKDF2 / AES-256-GCM 全自实现）；
   兼容旧版 Safari 的文件读取与样式。

7. 文档与发布
   使用说明、更新日志、README；
   GitHub 公开仓库与 v1.6 Release（三端成品）。

----------------------------------------------
二、技术要点
----------------------------------------------

· 密文容器（三端完全一致）
  魔术字 + 随机盐(16B) + IV(12B) + 原文件名 + 密文
  AES-256-GCM 加密，认证标签 16 字节；
  文件名参与认证（AAD 绑定），改文件名会导致解密失败。

· 密钥派生
  PBKDF2-HMAC-SHA256，600,000 次迭代，32 字节密钥。

· 多文件打包（MPKG 格式）
  先存放所有文件的名字和大小（头部区），再依次存放数据；
  解密时自动识别拆包，可一键打包成标准 ZIP
  （自实现 store 模式 ZIP，含 CRC32）。

· 密码写入文件名
  文件名非法字符用 %XX 转义；
  解密时自动从文件名读取密码，文件名没有密码或
  密码不匹配时可用手动输入兜底。

· Windows 版
  单个 exe 无外部依赖；bcrypt.dll 动态加载；
  图标注入不借助资源编译器，直接调用
  BeginUpdateResource / UpdateResource 系统接口。

· 安卓版
  不用 Gradle：javac → d8 → aapt2 → zipalign → apksigner；
  纯 Java 实现，无第三方库。

· Safari 兜底
  纯 JS 加密结果与 WebCrypto 字节级一致（已对拍验证）。

----------------------------------------------
四、踩过的坑与解决办法
----------------------------------------------

1. 容器头“文件名长度”字节序不一致（大端/小端）
   -> 三端统一为大端序。

2. 多文件包结构理解偏差（头与数据交错存放）
   -> 统一为“先全部头、后全部数据”。

3. 自实现 ZIP 漏写中央目录偏移，解压报错
   -> 补齐 EOCD 结构并实测验证。

4. TinyCC 头文件不全（winnls、资源接口等）
   -> 手动声明函数原型、动态加载 DLL。

5. TinyCC 不支持含中文的宽字符串字面量
   -> 界面文字一律运行时从 UTF-8 转换。

6. PowerShell 读无 BOM 脚本时中文乱码
   -> 所有构建脚本统一加 UTF-8 BOM。

7. MuMu 模拟器共享文件夹截断 adb 推送的文件名
   -> 仅影响测试文件推送；App 自身保存的文件名完整。

8. Safari 打开本地网页可能没有 WebCrypto
   -> 内置纯 JS 加密兜底，无缝切换。

9. GitHub 会把非 ASCII 的 Release 资产名改成 default.*
   -> 资产使用 ASCII 文件名，中文放到标签（label）显示。
